## Đo 500 Tag / 1 s, 10 client live, 60 s (x64)

| Số đo | MC (017, bench-500-mc) | Modbus (006-load-x64.json) |
|---|---|---|
| CPU trung bình (một nhân) | 0,2 % | 0,9 % |
| CPU max 5 s | 0,4 % | 1,4 % |
| RSS max | 15,6 MB | 12,3 MB |
| Chu kỳ Tag trung bình / p95 | 1 006,8 ms / 1 001 ms | 1 000 ms / 1 004 ms |
| Trễ PLC → client p95 / max | 3 ms / 5 ms | 19 ms / 30 ms |
| Mất sequence | 0 | 0 |
| Lệnh trên dây | 3 lệnh/s (D0/400, D1100/40, M0/5 word) | 4 lệnh/s (125 thanh ghi) |

Cùng cỡ với Modbus (SC-003). Số Modbus đo bằng bản runtime cũ hơn (feature 006, trước 1.1) nên chênh RSS ~3 MB và CPU không so sát được: chỉ kết luận cùng bậc. 011 không có số tải 500 Tag riêng.

## Lỗi runtime tìm thấy và đã sửa

Lần chạy đầu (`write` 51/52, `faults` 18/20) bắt được hai lỗi ở lớp API, cùng một nguyên nhân: `modbus::exceptionHex` in `code & 0xFF`.

1. Khóa end code trong `GET /api/v1/drivers/diagnostics` bị cắt còn 1 byte (C056 thành `"56"`).
2. Kết quả ghi bị end code từ chối trả `{"code":"5B","meaning":"mã lạ"}` thay vì C05B.

Sửa: `exceptionKey`/`exceptionJson` (`server/http/drivers_api.hpp`): mã > 0xFF là end code MC, viết 4 chữ hex (`"C056"`) kèm nghĩa theo `mcEndMeaning`; exception Modbus giữ 2 chữ. Studio đọc khóa 4 chữ hex (`mcEndCode`). Test: `DriversDiagApi.McEndCodesKeepTheirFourHexDigits`. Chạy lại `read`, `write`, `faults`: 5/5, 52/52, 20/20.

Không thấy lỗi ở đường đọc/ghi, gom khối, Random Read, chia khối, timeout, kết nối lại của `drivers/mc`.
